# MeaningForge v13 实施决策与冲突记录

更新日期：2026-08-29

本文只记录系统设计 v13 与当前可运行原型之间需要明确选择的地方。它不是新的需求清单，也不修改研究假设。

## 1. 三个视图入口与可用状态

**设计要求：** 叙事图谱、时空轨迹和解读空间是三个并列工作视图；原文联动是跨视图模块。

**实现冲突：** 完全隐藏条件视图会让参与者和研究者误以为功能被删除，也会改变顶部导航的位置，增加不同会话之间的界面差异。

**本轮决定：** 顶部始终保留“叙事图谱 / 时空轨迹 / 解读空间”三个固定入口。叙事图谱和解读空间始终可进入；只有时空轨迹可以因冻结包缺少最小事件/场景数据而禁用，并明确说明原因。

**实验影响：** 正式材料必须在实验前完成时空数据覆盖检查，因此同一材料的参与者不应看到不同的可用状态。点击禁用入口不记为一次视图使用。

## 2. 原文联动从第四视图迁移为全局模块

**设计要求：** 原文联动是第四个功能模块，但不是第四个并列视图。

**当前实现：** 旧版 `LinkedEvidenceView` 同时承担证据列表、证据详情和原文跳转。

**本轮决定：** 移除参与者界面的“原文联动”顶层标签，但不删除其逻辑。证据缩略轨常驻画布左侧，证据详情迁入固定检查器的“证据”标签；三个视图继续共用 `activeSpanId`、`activeEvidenceId` 和回到原文操作。

**后续整理：** 待集成测试稳定后，将历史组件名拆为 `EvidenceRail`、`EvidenceInspector` 和 `EvidenceLinkController`。在此之前保留 `LinkedEvidenceView` 名称，避免一次迁移同时改变入口、状态和数据协议。

## 3. 解读空间不设开启阈值

**旧设计冲突：** “至少两个可组织对象后开启”会把解读空间呈现为系统奖励，也会遗漏查询、回看证据、处理候选等从阅读走向组织的过程。

**本轮决定：** 解读空间从阅读开始即开放。空状态先显示阅读痕迹层；创建读者节点、关系或暂时理解后，再进入可比较的读者对象层。

**研究边界：** 已读跨度、背景查询、候选处理和证据回看只作为过程痕迹，不自动转写为解释，也不计入解释质量或意义数量。系统候选不进入读者对象层，除非读者明确采用或据此写下自己的对象。

## 4. 时空轨迹的数据不足

**设计要求：** 只使用冻结包中经过校准的事件和场景，不生成情感曲线或人物移动。

**本轮决定：** 冻结包至少包含两个事件或两个场景才启用入口。数据不足时禁用，不根据 LLM 临时补齐。

**实验影响：** 每份正式材料在冻结前必须通过时空数据覆盖检查；不同参与者使用同一冻结包。

## 5. 背景资料的当前结果与历史

**设计要求：** 当前查询置顶，历史默认折叠，正文不小于 14px；查询不创建读者节点。

**本轮决定：** “查背景”立即切换到固定检查器的“背景”标签并显示查询词和加载状态。返回后只显示最新去重结果，旧结果折叠。模型内容仍经过事实级过滤，界面明确标记“未外部核验”。

**保留边界：** 本地模型没有联网检索能力，因此模型给出的来源字段不作为已核验引文展示。

## 6. 选区动作与双击快捷操作

**设计要求：** 选区菜单先显示三个独立一级动作，添加和疑问再展开二级表单。

**当前实现冲突：** 旧版双击会直接创建或删除读者节点，可能绕过二级确认与名称检查。

**本轮决定：** 普通选区严格使用两级菜单；暂时保留双击快捷操作以兼容既有原型和历史实验数据。

**待讨论：** 正式实验模式是否完全关闭双击快捷操作。若保留，必须在实验说明中统一告知，并单独记录 `reader_ink_create` 的触发来源。

## 7. 本轮完成范围

- 三视图固定导航；解读空间始终开放，时空轨迹由冻结数据校验控制。
- 以人工校准 `narrative_graph` 取代信号载体拼接出来的故事骨架：29 个叙事对象、33 条中性关系，全部锚定原文。
- 叙事图谱采用章节分带、语义泳道、对象形状和前后主干编码；候选只在候选带浮现，不再与正式节点重叠。
- “线索”与“结构”不再复用同一种视觉状态：候选只在叙事图谱展开；结构开启后提供先后、人物参与、物件流转和共现四类关系镜头、数量、线型与原文样例。
- 时空轨迹不再读取自动抽取的低层谓词作为读者事件，改用冻结 `narrative_graph` 中的9个校准事件和5个校准场景；百分比范围改为章节筛选。
- 固定画布加独立滚动上下文检查器。
- 全局证据缩略轨、证据检查器和原文跳转迁移。
- 选区一级动作与按需二级表单。
- 背景资料加载态、当前结果、折叠历史和可读字号。
- 《药》4748 字全文冻结为正式参考包，包含 65 个 TextSpan（其中 64 个正文跨度）和每章 3 条候选。
- 两种条件使用共同的阶段、最终回答与精确证据字段；基线引用也记录原文跨度，而非只保留自由笔记。
- 后端拒绝未冻结材料和不完整会话，并导出 sessions、events、evidence links、final responses、reader objects、exclusions 和带哈希清单。

## 8. 正式材料与可比性的冲突

**当前状态：** 《药》全文冻结包已通过引用、关系端点、章节候选和材料注册校验，可用于两种条件的流程与可用性实验。

**尚未满足：** 用户实验方案采用两篇文本的被试内平衡设计，但拟作为文本 Y 的《竹林中》中文授权版本尚未取得并建立与《药》等级一致的冻结包。因此正式材料清单将其标为 `blocked`，不能用旧《阿Q正传》开发数据或其他占位数据代替。

**决定：** 在第二篇材料通过相同校验前，可以进行《药》的流程预实验或改为经审查的单材料设计；不能声称两篇材料的正式被试内实验已经就绪。共同最终回答和共同证据锚定是跨条件主要结果，MeaningForge 对象与基线笔记只用于条件内过程分析。

## 9. 尚未关闭的问题

- 对所有三种视图完成“文到图”的自动对象聚焦集成测试。
- 将检查器中的线程诊断内容进一步压缩为适合 300-320px 宽度的层级。
- 为检查器覆盖抽屉补充键盘焦点管理和 Esc 关闭。
- 决定正式实验是否关闭双击快速建点。
- 制作并人工核验第二篇正式材料的冻结包；在此之前不得启动两材料被试内主实验。
- 完成小规模预实验后再校准图谱密度、候选暴露上限和移动端/窄屏布局，不能只凭颜色继续微调。
